# 飞书首次接入向导

首次使用、连接失效或用户更换固定飞书目标时阅读。Agent 应一次只引导用户完成一个需要人工操作的步骤；能由脚本检查的内容直接检查，不要求用户猜测。

## 完成标准

以下项目全部成立才算接入完成：

1. 飞书企业自建应用已创建并启用；
2. 应用具备多维表格读写、必要的知识库节点读取和素材上传权限；
3. 目标多维表格已把该应用加入为文档应用或协作者并授予编辑权限；
4. App ID 和 App Secret 已在用户本机安全配置，聊天与日志中没有明文 Secret；
5. 固定多维表格链接、主赛道和受众已保存；
6. 只读连接测试成功；
7. 主赛道数据表已创建或复用，18 个字段齐全。

## 1. 创建飞书应用

引导用户打开飞书开放平台，创建“企业自建应用”。让用户自己登录、扫码、接受条款和处理验证码。记录 App ID；App Secret 只允许用户在本机凭证输入框或隐藏终端提示中输入。

## 2. 开通权限

至少开通：

- 查看、评论、编辑和管理多维表格；
- 固定链接为 `/wiki/` 时，开通知识空间节点读取权限；
- 上传评论截图需要云文档素材上传权限。

权限变更需要发布或生效时，等待用户完成发布后再测试。

## 3. 授权目标多维表格

在目标多维表格的分享或文档权限菜单中添加刚创建的应用，授予可编辑或可管理权限。找不到应用时，先确认该应用已开通至少一项多维表格 API 权限并已生效。

一个空白多维表格即可；脚本会创建字段。不要要求用户手工建立 18 个字段。

## 4. 安全保存凭证

Windows：

```powershell
python scripts/feishu_credentials.py --save --app-id <APP_ID>
```

Secret 由用户在隐藏输入提示中输入，Windows 使用当前用户 DPAPI 加密。macOS/Linux 使用当前终端会话环境变量，或让用户在其系统密钥管理器中配置后映射为：

```bash
export FEISHU_APP_ID="cli_xxx"
export FEISHU_APP_SECRET="..."
```

也可使用短期 `FEISHU_ACCESS_TOKEN`。已经出现在聊天、截图或日志中的 Secret 必须先在飞书后台重置。

## 5. 保存固定目标

```bash
python scripts/configure.py --bitable "<固定飞书多维表格链接>" --track "<主赛道>" --audience "<目标受众>" --comments-per-video 0 --upload-screenshots cited
```

`comments-per-video 0` 表示不设硬上限。固定目标是整个多维表格，不是某一张赛道表。

## 6. 测试并创建赛道表

先只读：

```bash
python scripts/feishu_bitable.py --test-connection
```

成功后再创建或复用主赛道表并补齐字段：

```bash
python scripts/feishu_bitable.py --ensure-track-table --track "<主赛道>"
```

若失败，只解释当前错误涉及的权限、目标或凭证，不让用户重新完成已经通过的步骤。

## 后续链接的落表规则

- 链接赛道与当前赛道相同：继续写入同一张赛道数据表；
- 链接赛道不同：在同一个固定多维表格中新建一张同结构数据表；
- 用户没有明确更换飞书链接：保持固定目标不变；
- 用户明确更换目标：重新确认授权并更新配置。
