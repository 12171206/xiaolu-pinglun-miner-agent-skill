# 从评论问题到选题

仅在生成或更新选题时阅读本文件。

## 低 Token 输入输出

先运行 `scripts/prefilter_comments.py`，模型只读取其紧凑候选 JSON。一次审核完整批次，输出供 `scripts/build_selection.py` 使用的最小结构：

```json
{
  "categories": [
    {
      "name": "栏目名",
      "reason": "共同受众任务或问题",
      "comment_ids": ["评论ID"]
    }
  ],
  "exclusions": [
    {"comment_id": "评论ID", "reason": "淘汰原因"}
  ]
}
```

生成阶段优先输出一个紧凑映射，值可为标题字符串，也可只包含确有必要的 `title`、`hook`、`outline`、`viral_reason`、`evidence_fit`。来源平台、URL、ID、时间、哈希和图片路径由本地脚本补齐。不要为每条评论重复输出这些元数据。

## 问题识别

先保留用户原话，再归纳问题。问题包括：

- 显式提问：问号、疑问词、求步骤、求推荐、求判断；
- 隐含提问：表达卡点、失败、担忧、反对、比较、预算或效果不确定；
- 高意图信号：询价、工具选择、服务流程、案例、风险、时间成本、是否适合自己。

情绪强不等于需求强。纯情绪、玩梗、互骂和无关引流不进入核心问题聚类。

## 入选门槛

先做负面排除，再生成选题。明显不能形成选题的评论直接淘汰，不截图、不生成题；其余评论仍须通过正面门槛。一条评论进入 `selected-comments.json`，至少同时满足：

- 能识别一个具体问题、目标、阻碍、选择或误区；
- 能泛化到赛道中的一类受众，而不是只有该用户个人才成立；
- 用户账号能给出可信、具体且合规的回答；
- 内容有实用价值、情绪张力、认知反差或行动意图中的至少一项。

### 截图独立成立测试

把视频标题、口播内容和相邻评论全部遮住，只看准备保存的评论截图。截图必须同时满足：

- 能明确看出讨论对象，例如哪类转账、赠与、消费、威胁或证据；
- 能明确看出具体争议或需求，而不是靠视频内容补全“这个、这种、中招、怎么办”的指代；
- 能从原文直接写出一句问题摘要，不添加原文没有的金额、关系、行为或法律结论。

缺少指代对象的简短追问、只说“我也遇到”“已经中招”“这个怎么破”的评论不入选。回复评论只有在父评论与回复能截在同一张图中、共同构成完整问题时才可入选。

以下评论不入选：纯表情或玩梗、无信息情绪、互骂、广告引流、重复复读、与赛道无关、只有无法核实的事实指控、信息过少无法判断语义。高风险个案只有在能匿名化并进行可靠核验时才可入选。

`selected-comments.json` 为对象数组，每项包含 `comment_id`、`selection_reason`、`proposed_category`、`question_summary` 和 `source_url`。未入选评论留在完整数据中，但不生成选题、不截图、不写入飞书证据区。

## 赛道分类

先使用固定配置中的栏目。每条问题簇只选一个主栏目，同时可加 1–3 个交叉标签。栏目判断依据是受众要完成的任务，不是视频平台或创作者名称。

固定栏目尚未建立时，根据用户的赛道、受众决策阶段和账号能力生成 4–8 个稳定内容支柱。栏目应覆盖明确且互斥度较高，例如认知、方法、工具、案例、风险、选择决策；具体名称必须使用用户赛道语言。把本轮建议栏目写入报告，后续保持名称一致，除非用户要求调整。

## 聚类规则

按“同一受众任务 + 同一决策障碍”聚类，而不是只看词面相似。每个聚类保留：

- `cluster_id` 与一句话问题；
- 评论数、视频数、不同作者数；
- 2 至 5 条代表性原话；
- 共识、分歧和例外；
- 与用户赛道的关系；
- 是否存在明显样本偏差。

一个聚类只有一条评论时可以生成选题，但必须标记为“单点信号”。跨至少两个视频出现的独立问题优先级更高。

## 爆款潜力评分

每项按 0–5 分评分，再换算为 100 分：

| 维度 | 权重 | 判断 |
|---|---:|---|
| 需求密度 | 25 | 评论数、视频数、作者去重后的覆盖 |
| 情绪与痛点 | 20 | 卡点、损失、焦虑、渴望或迫切程度 |
| 冲突与好奇 | 15 | 反常识、争议、认知落差或结果悬念 |
| 行动意图 | 15 | 是否接近选择、购买、执行或求方案 |
| 收藏分享价值 | 15 | 是否适合清单、步骤、避坑、对比或可复用模板 |
| 赛道匹配 | 10 | 是否符合用户能力、受众和账号信任基础 |

总分 = 各维度分数 ÷ 5 × 对应权重。分数相同优先选择跨视频出现、能在前三秒说清冲突、可提供具体解决方案且风险更低的题目。不要用虚假精确度掩盖小样本；报告中同时给出原始计数。“爆款潜力”是内容假设，不是流量承诺。

选题优先级：80–100 为 A 级，65–79 为 B 级，50–64 为 C 级，低于 50 只进入待验证。小样本单点信号最高标为 B 级，除非用户提供了其他独立证据。

## 每个选题的完成定义

### 选题—截图匹配

生成标题后逐字回查截图。标题、钩子和核心命题中的事实要么能在截图中直接找到，要么只是对截图中多个具体个案的保守归纳。金额、关系时长、过错行为、款项性质、诉讼状态和结果不得由模型补写。

为每个正式选题记录一句 `evidence_fit`：说明截图原文具体支持标题中的哪一部分。无法写出这句，或需要用视频内容解释截图，选题降为待验证并移出正式选题。一个题可引用多张截图，但至少一张必须独立支持核心命题；一张截图也不能被牵强分配给不相符的题目。

每个正式选题包含：

1. 选题核心命题与 3 个标题版本：直接利益型、冲突反差型、问题代入型；
2. 对应用户问题，尽量贴近原话；
3. 目标受众与使用场景；
4. 前三秒钩子，以及观众继续观看的理由；
5. 核心冲突、内容承诺与三段式大纲；
6. 可制造收藏或分享的具体交付物；
7. 差异化观点或证据；
8. 至少一条独立支持核心命题的评论引用、来源 URL、评论 ID、截图文件和 `evidence_fit`；
9. 六维评分、总分、等级与置信度；
10. 事实核验点、合规风险或可能误导之处；
11. 推荐内容形态：短视频、口播、图文、直播切片或长内容。

## 报告结构

`topic-report.md` 使用以下顺序：

1. 研究简报；
2. 样本与采集覆盖；
3. 赛道栏目与分类说明；
4. 高频问题地图；
5. 选题优先级总表；
6. 按栏目分组的逐条选题卡；
7. 待验证信号；
8. 失败链接与局限；
9. 证据索引。

引用使用匿名标签，例如“评论者 A-17”，同时保留 `comment_id` 便于从 `selected-evidence.json` 回查原始截图。
